# Кодогенерация в C

Заключительный этап разработки модуля — трансляция схемы в исходный код на C
встроенным кодогенератором SimInTech.

## Главное, что нужно знать

**Кодогенерацию нельзя запустить на любой машине.** Количество лицензий на
неё ограничено, поэтому генерация выполняется либо на выделенном компьютере,
либо через сборочный конвейер (CI). На рядовом рабочем месте разработчика
нужный пункт меню может просто отсутствовать — это не поломка установки.

## Процедура

### 1. Проверьте имя модуля

Имя прикладного модуля (динамической библиотеки) должно соответствовать
правилам наименования, принятым в вашем проекте. Переименование после
генерации обойдётся дороже, чем проверка до неё.

### 2. Загрузите конфигурацию кодогенератора

Окно **«Кодогенератор Си»** → вкладка **«Загрузка»** → кнопка
**«Загрузить конфигурацию»** → укажите файл `.alt` (см. `file-formats.md`).
Файл содержит параметры компиляции, ключевые макросы и настройки целевой ОС.

### 3. Локальная проверочная генерация

Для быстрой проверки модели без привязки к целевой платформе:

**«Инструменты» → «Сгенерировать программу»**

Дождитесь завершения и посмотрите окно сообщений:

- **Успех** — строка вида «Исходные тексты программы сгенерированы» с путями
  к созданным файлам;
- **Ошибки и предупреждения** — список диагностических сообщений.

> Двойной клик по сообщению переводит к блоку, который его вызвал. Это самый
> быстрый способ найти проблемное место в большой схеме.

### 4. Устраните все сообщения

Устранить нужно **все** предупреждения и ошибки, а не только ошибки.
Предупреждение, оставленное без внимания, обычно означает, что часть логики
не попала в сгенерированный код.

### 5. Добавьте модуль в таблицу проектов

Это **завершающий** шаг — он выполняется только после успешной проверочной
генерации и полного устранения замечаний. После загрузки конфигурации
в окне «Кодогенератор Си» становится доступна таблица проектов; для модуля
указываются:

| Колонка | Что задавать |
|---------|--------------|
| Файл схемы | путь к `.prt` |
| Имя алгоритма | идентификатор проекта по правилам наименования |
| Период, мс | период вызова расчётного модуля |
| К-во вызовов | по умолчанию 1 |
| Образ (exe) | имя исполняемого файла проекта |

## Генерация скриптом

Для автоматизации в каталоге `scripts/build/` проекта есть `code_generate.bat`
с двумя режимами:

```cmd
:: все модули из таблицы проектов
scripts\build\code_generate.bat all

:: один конкретный модуль
scripts\build\code_generate.bat C:\<путь>\module.prt
```

Успешная генерация складывает исходники в `config_build\libs\`.

Через командную строку ту же операцию выполняет ключ `/gencode`
(см. `cli.md`).

## Типы данных при передаче сигналов

Три правила, которые чаще всего застают врасплох:

1. **Сигнал из базы данных наследует свой тип** — вещественный, целый и так
   далее. Тип задаётся в базе, а не в схеме.
2. **Сигнал, переданный по линии связи** (между подсистемами или через
   интерфейсы), **всегда приводится к `double`**. Это стандартное поведение
   SimInTech. Исключение — явное приведение типа внутри блока «Язык
   программирования»: там заданный тип сохраняется.
3. **Универсального блока приведения типов в библиотеке нет.** Преобразование
   `double` → `integer` делается либо скриптом в блоке «Язык программирования»,
   либо математическими блоками с нужным округлением.

Пример приведения в блоке:

```simintech
input u: double;
output y: integer;

begin
    y = u;
end;
```

## Предостережения

- **Поле «Секция запоминания состояний» должно оставаться пустым.** Если
  в свойствах блока «Язык программирования» явно указать там значение `0`,
  кодогенератор попытается транслировать секцию состояния по шаблону
  встроенного языка, несовместимому с C-шаблоном проекта, и генерация упадёт
  с ошибкой разбора. Поле заполняют осознанно только при использовании
  пользовательского шаблона генерации кода на C.
- Ошибки деления на ноль и отрицательного аргумента `sqrt` транслятор
  **не** выявляет анализом потока управления: конструкция
  `if tmp > 0 then sqrt(tmp)` не гарантирует прохождения генерации. Защищайте
  знаменатель и аргумент явно.
- Тип блока может не поддерживаться кодогенерацией вовсе — тогда блок
  заменяют на «Язык программирования» (см. `language/pitfalls.md`).
- Если генерация падает без внятного сообщения, ищите причину в конфигурации
  `.alt`: параметры `encoding` и `translit_style` влияют на имена
  в сгенерированном коде, и при рассогласовании сборка не находит символы.

Полный каталог ошибок и их причин — в `language/pitfalls.md`.
