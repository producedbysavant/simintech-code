# Макросы SimInTech

Макрос — скрипт, который управляет проектом снаружи: открывает схемы, читает
и правит свойства объектов, выгружает данные. Макрос запускается ключом
`/macros` или `/projmacros` (см. `cli.md`).

## Это другой язык

Макроязык **не совпадает** с языком блока «Язык программирования» из
`language/syntax.md`. Это важно: набор операторов шире, потому что макрос
исполняется интерпретатором, а не транслируется в C.

| | Язык блока | Макроязык |
|---|---|---|
| Обёртка тела | `begin ... end` | `initialization ... end;` |
| Оператор `#` (размножение) | не транслируется | работает |
| Оператор `&` (объединение) | не транслируется | работает |
| Динамические массивы | запрещены | работают |
| Кодогенерация в C | да | нет |

Отсюда практическое следствие: приём, недопустимый в блоке, часто допустим
в макросе. Не переносите макро-конструкции в блоки и наоборот.

## Структура

```
initialization
  // тело макроса
end;
```

Типичный макрос выгрузки базы сигналов из пакета проектов:

```
initialization
  packid = openpack("dbpak.pak", 0);
  initpack(packid, 0);
  projid = getpackprojectid(packid, 0);
  dbexporttoxml(projid, "signals.xml");
  closepack(packid, 0);
  closeapp;
end;
```

Инициализация проекта:

```
var proj_id, obj_id;
proj_id = GetCurrentProjectID;
InitProject(proj_id, TRUE);
obj_id = getmainpageid(proj_id);
```

Обратите внимание: `var` в макросе объявляет имена без типов — это
отличие от языка блока, где каждая переменная требует явного типа.

## Команды

### Проекты и пакеты

| Команда | Назначение |
|---------|-----------|
| `openproject(path, 0)` | Открыть проект, вернуть идентификатор |
| `initproject(id, 0)` | Инициализировать проект |
| `openpack(path, 0)` / `closepack(id, 0)` | Открыть и закрыть пакет проектов |
| `initpack(id, 0)` | Инициализировать пакет |
| `getpackprojectid(packid, index)` | Идентификатор проекта внутри пакета |
| `getcurrentprojectid` | Идентификатор текущего проекта |
| `getmainpageid(projid)` | Идентификатор главной страницы схемы |
| `closeapp` | Закрыть приложение |

Второй аргумент `0` у `openproject`, `initproject`, `openpack` и подобных
команд — режим открытия. Его точная семантика в справке не раскрыта;
на практике используется `0`.

### Объектная модель

| Команда | Назначение |
|---------|-----------|
| `getobjcount(container)` | Число объектов в контейнере |
| `getobj(container, index)` | Объект по индексу |
| `getpropdata(obj, "Prop")` | Прочитать свойство объекта |
| `setprop(obj, "Prop", value)` | Записать свойство |
| `getobjclassname(obj)` | Имя класса блока (например, «Сумматор») |
| `getfullname(obj)` | Полное имя объекта |
| `getcurrentcontainer` | Текущий контейнер |
| `getsubmodelid(obj)` | Идентификатор вложенной субмодели |
| `getblockportcount(obj, mode)` | Число портов блока |
| `getblockportid(obj, index, mode)` | Идентификатор порта |
| `getportinfo(port)` | Информация о порте |
| `getportwires(port)` | Связи порта |
| `findendport(wire, end)` | Противоположный конец связи |

Поиск объектов по классу идёт сравнением результата `getobjclassname`
с русским именем класса: `«Субмодель»`, `«Порт входа»`, `«Запись в базу сигналов»`.

### Строки и массивы

`strcopy`, `length`, `pos`, `lowercase`, `floattostr`.

Массив объявляется с типом и инициализируется пустым:

```
var arr: intarray;
arr = [0#0];              // ноль повторов — пустой массив

arr = arr & id[1];        // присоединить элемент
```

### Диагностика

`seterrorstr(...)` пишет сообщение в протокол и может связать его
с конкретным объектом — так работает статический анализ схемы,
который находит проблемные блоки и указывает на них.

Важно: `seterrorstr` работает **только в макросе**. В коде блока он
не транслируется в C (см. `language/pitfalls.md`).

## Подпрограммы

Макрос поддерживает функции и процедуры с типизированными параметрами
и выходными параметрами `out`:

```
procedure FillObjectsArray(container, out arr: intarray)
  ...
  arr = arr & found;
end;

function FindObjectsID(container): intarray
  var arr: intarray;
  ...
  FindObjectsID = arr;    // возврат — присваивание имени функции
end;
```

Возврат значения — присваиванием имени функции. Локальную переменную
можно объявить прямо в теле цикла.

## Кавычки и экранирование

Строки — в двойных кавычках. Кавычка внутри строки удваивается, как
в Pascal:

```
dbexporttoxml(projid, "file""name.xml");   // файл file"name.xml
```

Правило то же, что и в языке блока.

## Регистр

Регистр не различается: `openproject` и `OpenProject` — одна и та же
команда. Это согласуется с языком блока (`language/syntax.md`).

## Предостережения

- Файлы макросов в реальных проектах лежат в разных кодировках — от
  Windows-1251 до UTF-8 без BOM. Если макрос содержит кириллицу,
  проверьте кодировку файла, иначе сравнение с русскими именами классов
  не сработает.
- Значения свойств, содержащие кавычки и переносы строк, требуют
  экранирования — иначе макрос разберётся не так, как вы ожидали.
- Результат макроса возвращается не как значение функции, а через файл,
  который макрос записал, либо через код возврата процесса.
- Макрос — код интерпретируемый; ошибка в нём обнаруживается при запуске,
  а не при сохранении.
