# Форматы файлов SimInTech

## Схемы и проекты

| Расширение | Что это | Читается текстом |
|-----------|---------|------------------|
| `.prt` | Проект (схема) — основной формат | Нет, бинарный |
| `.xprt` | Тот же проект, выгруженный в XML | Да |
| `.pak` | Пакет проектов: несколько схем в одном окне | Да |
| `.mgr` | Графические элементы: окна анимации, панели | Нет |

**Внимание:** расширения `.prj` у проектов SimInTech **нет**. В ранних
материалах этой библиотеки оно упоминалось ошибочно. Проект — это `.prt`,
а его текстовое представление — `.xprt`.

### `.prt` — проект

Бинарный формат, текстовым редактором не правится. Единственный надёжный
способ получить его содержимое — выгрузить в `.xprt` средствами самого
SimInTech (макросом или через COM-интерфейс), а после правки собрать
обратно.

### `.xprt` — проект в XML

Выгружается методом `SaveProjectXML` (COM) или командой `dbexporttoxml`
для базы сигналов. Свойства, которые нужно знать при разборе:

**Кодировка — UTF-8 с BOM.** Так пишет `SaveProjectXML` (проверено на
настоящих выгрузках: BOM `EF BB BF` и объявление `encoding="utf-8"` в самом
XML). cp1251 может попасться от старых версий, поэтому кодировку выбирают по
содержимому — `simintech_api.catalog.decode_xprt`.

Читать `.xprt` как cp1251 нельзя: кириллица превратится в мусор **молча** —
cp1251 декодирует любые байты, и ошибки не будет. `errors="replace"` тоже не
выход: он прячет порчу файла вместо того, чтобы о ней сообщить.

**Строковые значения обёрнуты в обратные кавычки.** В XML имя объекта
хранится не как `Сумматор_1`, а как `` `Сумматор_1` ``. При разборе
бэктики нужно снимать. То же правило действует и для XML базы сигналов
(см. `signal-db.md`).

**Тело скрипта кодируется числовыми эскейпами.** Код блока «Язык
программирования» лежит в свойстве `Script`, где служебные символы
заменены на `#<код>`:

| Эскейп | Символ |
|--------|--------|
| `#13#10` | перевод строки (CR LF) |
| `#9` | табуляция |
| `#60#62` | `<>` |

**Графические объекты лежат вперемешку с блоками.** При извлечении списка
блоков из `.xprt` нужно отфильтровать элементы оформления: `Wire`, `Arc`,
`Line`, `Point`, `PolyLine`, `Polygon`, `Rect`, `Rectangle`, `RotatedText`,
`TextLabel`, `Button`, `Комментарий` и подобные. Иначе в списке сигналов
окажутся подписи и линии связи.

### `.pak` — пакет проектов

Текстовый файл в UTF-8 (с BOM). Содержит секции:

```
[Form]
[Common]
[Files]
Count=2
0=project_a.prt
1=project_b.xprt
[Active]
[TimeSync]
```

Пакет нужен для совместного расчёта нескольких схем — например, когда
модель объекта и модель регулятора лежат в разных проектах.

## Кодогенерация

| Расширение | Что это |
|-----------|---------|
| `.alt` | Конфигурация кодогенератора в C |
| `.inc` | Сгенерированный C-код, а также тела скриптов |
| `.h` | Заголовочный файл сгенерированного модуля |
| `_init.inc`, `_state.inc` | Инициализация и хранение состояний модели |
| `.extvars.table`, `.intvars.table` | Таблицы внешних и внутренних переменных |

### Конфигурация `.alt`

Задаёт, какие проекты генерировать и с какими параметрами. Основные секции:

- `[filelist]` — перечень модулей: путь к `.prt`, имя алгоритма (`algoname`),
  период вызова, число вызовов, имя выходного модуля. Количество задаётся
  ключом `count`, дальше идут пронумерованные строки `itemN`, `algonameN`,
  `periodN`, `callcountN`, `exenameN`.
- `[debug]` — параметры генерации: каталог исходников, шаблон сборки,
  `encoding`, `translit_style`, `header_style`, `f_global_divide_check`.

Отсюда два важных следствия. Во-первых, `translit_style` и `encoding`
определяют, как русские имена превратятся в идентификаторы C — при
рассогласовании имён сборочный конвейер не найдёт символы. Во-вторых,
`f_global_divide_check` включает проверку деления на ноль на уровне
кодогенератора: это тот случай, когда ошибку ловит сама генерация,
а не анализ в блоке (см. `language/pitfalls.md`).

### Признак успешной генерации

После кодогенерации для каждого алгоритма должен появиться полный набор
файлов: `.h`, `.inc`, `_init.inc`, `_state.inc`, `.extvars.table`,
`.intvars.table`. Отсутствие любого из них — признак сбоя, даже если
код возврата процесса был нулевым.

## Библиотеки блоков

Библиотеки блоков — файлы `.csl` в каталоге `bin` установленного SimInTech.

## Итог по кодировкам

| Файл | Кодировка |
|------|-----------|
| `.xprt` | UTF-8 (с BOM) |
| База сигналов в XML | Windows-1251 |
| `.pak` | UTF-8 (с BOM) |
| `.prt`, `.mgr`, `.db` | бинарные |
| Файлы макросов | не унифицировано — встречаются cp1251 и UTF-8 |

Разнобой кодировок — источник большинства ошибок при автоматизации.
Если кириллица превратилась в мусор, первым делом проверяйте кодировку
файла, а не логику разбора.
