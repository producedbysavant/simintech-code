# Запуск SimInTech из командной строки

Исполняемый файл — `mmain.exe`. При типовой установке он лежит в
`C:\SimInTech64\bin\mmain.exe`; в WSL тот же путь доступен как
`/mnt/c/SimInTech64/bin/mmain.exe`.

Все ключи ниже проверены практикой на реальных проектах. Формально это
не документированные опции, поэтому при обновлении SimInTech их стоит
перепроверить.

## Ключи

| Ключ | Назначение |
|------|-----------|
| `<файл>` | Проект или пакет, который нужно открыть |
| `/silentmode` | Тихий режим: без диалогов и окон |
| `/start` | Инициализировать проект (собрать модель) |
| `/run` | Запустить расчёт |
| `/runstep` | Выполнить один шаг расчёта |
| `/exitonstop` | Выйти по окончании расчёта |
| `/macros <файл>` | Выполнить файл макроса |
| `/projmacros <файл>` | Выполнить макрос в контексте проекта |
| `/gencode` | Выполнить кодогенерацию в C |
| `/saveas <путь>` | Сохранить проект в другом формате |
| `/setparameter <имя> <значение>` | Задать параметр проекта |
| `/sleep {<мс>}` | Пауза перед следующим действием |
| `/close` | Закрыть проект |
| `/exit` | Закрыть приложение |
| `//cgloadconfig <файл>` | Загрузить конфигурацию кодогенератора |

`/silentmode` добавляйте всегда, когда процесс запускается не человеком:
без него SimInTech показывает диалоги, и процесс зависает в ожидании ответа.

## Типовые командные строки

Расчёт проекта:

```
mmain.exe /silentmode project.prt /start /run /exitonstop
```

Расчёт пакета проектов:

```
mmain.exe /silentmode /start /run /exitonstop 0.CAP.pak
```

Выполнение макроса:

```
mmain.exe /silentmode /macros macros.txt
```

Кодогенерация:

```
mmain.exe "project.prt" /start /silentmode /gencode /close /exit
```

Макрос в контексте проекта:

```
mmain.exe "project.prt" /projmacros "ModelAdvisor.txt" /sleep {50} /silentmode /close /exit
```

Командная строка собирается как список аргументов, а не как строка для shell.
Кавычки и экранирование путей делает вызывающая система; в Python это
`subprocess.run([...])` со списком, а не со строкой.

## Переменные окружения

| Переменная | Назначение |
|------------|-----------|
| `SIMINTECH_PATH` | Каталог с `mmain.exe` (именно каталог, не путь к файлу) |
| `SIMINTECH` | Альтернативная переменная с тем же смыслом |

Если переменные не заданы, разумно искать `mmain.exe` в
`C:\SimInTech64\bin\` и `/mnt/c/SimInTech64/bin/`.

## Кодировка вывода

`mmain.exe` пишет вывод в **Windows-1251 (cp1251)**, даже когда запущен
под WSL. Читать вывод нужно в бинарном режиме и декодировать как cp1251,
иначе кириллица в сообщениях превратится в мусор:

```python
import subprocess

result = subprocess.run(
    [mmain, "/silentmode", project, "/start", "/run", "/exitonstop"],
    capture_output=True,
    timeout=600,
)
text = result.stdout.decode("cp1251", errors="replace")
```

Если cp1251 не подошла, имеет смысл попробовать cp866, затем utf-8 — на
разных сборках поведение отличается.

Лог самого движка — `C:\SimInTech64\bin\simintechLog.txt`.

## Коды возврата

`0` — успех. Но полагаться только на код возврата нельзя: на этапе
`closeapp` процесс может завершиться с ненулевым кодом (на практике
встречается `3221226525`, то есть `0xC000041D`), хотя вся полезная работа
уже выполнена и файлы выгружены. Поэтому проверять надо **артефакты**,
а не только код возврата:

- для кодогенерации — наличие и непустоту сгенерированных файлов;
- для выгрузки данных — существование и корректность итогового файла.

## Запуск на Linux без WSL

Конструкция с `wine` существует, но считается вспомогательной и менее
надёжной, чем WSL:

```
WINEDLLOVERRIDES=winemenubuilder.exe=d wine mmain.exe /silentmode ...
```

Для рабочих конвейеров предпочтителен WSL: вызов
`wsl -d <дистрибутив> --cd <каталог> bash -c "..."` из Windows-скрипта.

## Предостережения

- Ключи `/saveas` и `/setparameter` принимают значение с пробелами
  ненадёжно: передавайте путь или значение без пробелов.
- Без `/exitonstop` процесс расчёта не завершится сам — он останется ждать.
- `mmain.exe` не освобождает ресурсы мгновенно: если запускаете его
  в цикле, убедитесь, что процесс действительно завершился, прежде чем
  стартовать следующий.
- Конфигурация кодогенератора (файл `.alt`) содержит параметры кодировки
  и транслитерации — они влияют на имена в сгенерированном C-коде.
