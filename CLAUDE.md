# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Что это за репозиторий

Документационный проект: открытая библиотека кода, примеров и справочных
материалов по **SimInTech** — российской среде моделирования динамических
систем. Исходного кода, сборки, тестов и CI здесь нет — только Markdown.

Весь текст — на русском. Идентификаторы, синтаксис и названия блоков —
на английском либо в формате «Блок "Интегратор" (Integrator)».

## Команды

Отсутствуют. Нет сборки, линтера, тестов, `package.json` и CI. Единственная
содержательная проверка — работоспособность примеров кода при кодогенерации
в C (клавиша F9 в SimInTech) и соответствие шаблонам ниже.

## Канонический синтаксис

`language/syntax.md` — **источник истины**. Если пример ему противоречит,
прав пример. Кратко:

- Объявления плоские, каждое с явным типом: `input u: double;`, `output y: double;`,
  `const K = 2.5, N = 10;`, `var y: double;`. Запись `var a, b, c: double;` недопустима.
- Тело — `begin ... end`; есть необязательная секция `finalization ... end;`.
- Условие — `if x > 0 then begin ... end else begin ... end;`
- Цикл — `for (idx = 1, N) do begin ... end;`, `while ... do begin ... end;`
- Сравнения `=` и `<>` (НЕ `==`, НЕ `!=`); логика `and`, `or`, `xor`.
  Оператор `not` не поддерживается — отрицание через `flag = false` / `flag <> true`
- Массивы только статические: `var R[MAX]: array;` / `intarray`; **индексация от 1**;
  индекс — переменная, а не выражение
- Системные переменные: `time`, `hmax` / `hmin`. **`T`, `dt`, `Nstep`, `Tstop` системными не являются**
- Запрещены имена `i`, `j`, `c` — конфликтуют с авто-счётчиками транслятора
- Не транслируются в C: `#`, `&`, `..`, `seterrorstr`, прямое присваивание массивов,
  матричные операции, тип `string`
- Примеры кода помечаются ```` ```simintech ````

**Макроязык (`automation/macros.md`) — другой язык.** В нём работают `#`, `&`,
динамические массивы и `seterrorstr`, потому что макрос исполняется
интерпретатором, а не транслируется в C. Не переносите конструкции между
блоками и макросами.

## Устаревший синтаксис

Ранее весь репозиторий был написан в чужом диалекте. Сейчас он вычищен, и
старые конструкции встречаются только как **намеренные контрпримеры**
«так не надо» — в `language/pitfalls.md`, `tutorials/02`, `tutorials/03`,
`.github/pull_request_template.md`. Это ожидаемо, не «исправляйте» их.

Сам диалект, чтобы узнавать его в чужом коде: секции `function` / `input:` /
`output:` / `var:` / `begin:`, операторы `end_if`, `end_for`, `elsif`,
циклы `for i = 0 to n do`, индексация с нуля, `==` и `!=`, `not`,
вызовы `getStepSize()` / `getCurrentTime()` / `getParameter()`.

## Работа с фактами

Библиотека собирается из практики эксплуатации SimInTech, а не из пересказа
справки. Правила:

- **Не выдумывайте** имена блоков, свойств, функций и макро-команд. Если факт
  не подтверждён — опустите его или пометьте как непроверенный.
- В `blocks/*.md` таблица «Параметры» содержит **реальные имена свойств**.
  Часть из них подтверждена работой через COM-интерфейс (`Константа` → `y0`,
  `Сумматор` → `a` / `xn`, `Интегратор` → `k` / `x0`, `Ступенька` → `t` / `y0` / `yk`,
  `Усилитель` → `a`); там, где подтверждения нет, стоит явное предупреждение.
  Сохраняйте это различие.
- **Расширения `.prj` у проектов SimInTech нет.** Проект — `.prt` (бинарный)
  или `.xprt` (XML). Если встретите `.prj` — это ошибка.
- Не переносите в публичный репозиторий сведения о внутренней инфраструктуре
  организаций: адреса, учётные данные, названия заказчиков, выдержки из
  закрытых технических заданий.

## Процесс

Ветка `main` защищена: прямой push запрещён, изменения идут только через
pull request (см. `.github/`). Требуется одно ревью. Для администратора
репозитория включён обход защиты — он может смержить свой PR без второго
ревьюера и запушить напрямую; строгость защиты на него не распространяется.
Скрипт `scripts/setup-branch-protection.sh` повторно применяет настройки
защиты — он же служит их документацией.

При написании нового материала:

- новый блок — отдельный файл в `blocks/<категория>/` по шаблону из `CONTRIBUTING.md`;
- заголовок файла — на русском, английский термин в скобках;
- кодировка UTF-8, переводы строк LF, финальный перевод строки;
- раздел «Предостережения» — это конкретные грабли с симптомом и решением
  (насыщение, алиасинг, размер шага, границы массивов), а не общие советы.
