# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Что это за репозиторий

Две части в одном репозитории:

1. **`simintech_api/`** — Python-библиотека `simintech-api`: управление
   SimInTech через внешний COM API (`IMVTU_Server`, сервер `mmain.exe`).
   Именно её оборачивает MCP-сервер `simintech-mcp`.
2. **Справочный контент** — `language/`, `blocks/`, `patterns/`, `tutorials/`,
   `automation/`. Markdown, целиком на русском; идентификаторы, синтаксис и
   названия блоков — на английском либо в формате «Блок "Интегратор" (Integrator)».

**COM работает только на Windows** и требует `mmain.exe /regserver`. На Linux
библиотека ставится и проходят unit-тесты; COM-вызовы недоступны.

## Команды

```bash
pip install -e ".[test]"        # библиотека + pytest (comtypes — маркер win32)
python3.11 -m pytest tests/unit -q                         # 171 тест, без COM
python3.11 -m pytest -q                                    # то же: интеграция и бенчмарки отсеяны (addopts)
python3.11 -m pytest tests/integration -m integration -q   # Windows + реальный COM
python3.11 -m pytest -m performance -q                     # бенчмарки (меряют стенные часы)
flake8                                                     # настройки — в .flake8
simintech-cli                   # консольный вход в библиотеку
simintech-generate-catalog      # перегенерация data/block_catalog.json (нужен COM)
```

Для контентной части содержательная проверка — работоспособность примеров кода
при кодогенерации в C (меню «Инструменты» → «Сгенерировать программу») и
соответствие шаблонам ниже.

## Библиотека: ключевые факты

- **COM привязан к потоку.** `CoInitializeEx` вызывается в `COMClient.connect()`
  для текущего потока; объект, созданный в чужом потоке, даёт
  `CO_E_OBJNOTCONNECTED`. Поэтому в `simintech-mcp` все вызовы идут через один
  выделенный поток.
- **`SetBlockProp` не отвергает неизвестное имя параметра** — отказ молчаливый.
  Имена короткие и неочевидные: у «Константы» — `a`, у «Сумматора» — `a`
  (веса входов), у «Интегратора» — `k`/`x0`. Источник истины —
  `simintech_api/data/block_catalog.json`, а **не** `blocks/*.md` и не
  `examples/`: там встречаются несуществующие имена.
- **`SetBlockProp("Name", ...)` не переименовывает блок** — имя остаётся
  автоматическим (`k_0`, `kx_0`). Соединять и искать блок надо по этому имени.
- **Сигналы читаются только у проекта с базой сигналов.** У проекта из
  `Project.new()` базы нет: `list_signals()` вернёт имена блоков с пометкой
  «не читается» — это отсутствие данных, а не ошибка.
- **`Project.new()` даёт неработающий проект — не считает.** `NewProject`
  создаёт пустой проект: без расчётного слоя («Автоматика»,
  `$(Root)\mbtylib.dll@layer`) и без секции настроек расчёта. В нём модельное
  время не растёт **ничем** — `ProjectRun`, `RunTo`, `WaitForTime`,
  `ProjectStep` возвращают успех, а `get_time()` остаётся `0.0`; не помогают
  `save_binary` с переоткрытием, `WaitForAllLoading` и `SetSilentMode(0)`.
  Создавать проект надо из шаблона: `Project.from_template(client)` —
  «Схема модели общего вида.prt» из поставки (`find_model_template()`,
  переменные `SIMINTECH_TEMPLATE`/`SIMINTECH_PATH`).
- **Время расчёта задаётся свойством слоя.** `set_calc_end_time(секунды)` →
  `SetLayerProp(ProjectId, 0, "endtime", "<строка>")`; у шаблона по умолчанию
  `10` с. Возврат `0` вместо handle означает, что расчётного слоя нет (проект
  из `Project.new()`). Там же живут `starttime`, `hmin`, `hmax`, `intmet`.
- **Неподключённый вход останавливает расчёт всей модели — молча.** Если у
  блока вход ни с чем не соединён, `get_time()` остаётся `0.0` и ошибки нет.
  Проверено: «Константа → В файл» связана — время доходит до `1.0`; та же схема
  с висящим входом у «В файл» — `0.0`; одна «Константа» без «В файл» — снова
  `1.0`. Это первое, что нужно проверять при «расчёт не идёт».
- **Результат независимо от базы сигналов даёт блок «В файл».** Он пишет по
  строке на момент времени: `<время> <значение 1> … <значение n>`
  (`filename`, `count`, `step`, …). Это основной способ получить результат:
  `get_signal` требует проекта с подключённой базой сигналов.
- **Расчёт остановится на `endtime`, а не на `to_time`.** `run_to` доводит
  время только до конечного времени расчёта; большее `to_time` недостижимо,
  пока не поднят `endtime` (`Project.set_calc_end_time`).
- **`layout_place` в MCP применяет координаты** (`set_center`), а не только
  считает их: блоки действительно перемещаются. Позицией можно управлять и при
  создании (`add_block(x=, y=)`).

## Канонический синтаксис

`language/syntax.md` — **источник истины**. Если пример ему противоречит,
прав пример. Кратко:

- Объявления плоские, каждое с явным типом: `input u: double;`, `output y: double;`,
  `const K = 2.5, N = 10;`, `var y: double;`. Запись `var a, b, c: double;` недопустима.
- Тело — `begin ... end`; есть необязательная секция `finalization ... end;`.
- Условие — `if x > 0 then begin ... end else begin ... end;`
- Цикл — `for (idx = 1, N) do begin ... end;`, `while ... do begin ... end;`
- Сравнения `=` и `<>` (НЕ `==`, НЕ `!=`); логика `and`, `or`, `not`, `xor`.
  `not` поддерживается, но условия рекомендуется писать в утвердительной форме
  (принцип позитивного программирования, см. `language/syntax.md`)
- Массивы только статические: `var R[MAX]: array;` / `intarray`; **индексация от 1**;
  индекс — переменная, а не выражение
- Системные переменные: `time`, `stepsize`. **`T`, `dt`, `Nstep`, `Tstop` переменными не являются**, а `hmax`/`hmin` — это параметры расчёта (настройки проекта), а не переменные языка
- Запрещены имена `i`, `j`, `c` — конфликтуют с авто-счётчиками транслятора
- Не транслируются в C: `#`, `&`, `..`, `seterrorstr`, прямое присваивание массивов,
  матричные операции, тип `string`
- Примеры кода помечаются ```` ```simintech ````

**Макроязык (`automation/macros.md`) — другой язык.** В нём работают `#`, `&`,
динамические массивы и `seterrorstr`, потому что макрос исполняется
интерпретатором, а не транслируется в C. Не переносите конструкции между
блоками и макросами.

## Устаревший синтаксис

Ранее весь репозиторий был написан в чужом диалекте. Сейчас он вычищен, и
старые конструкции встречаются только как **намеренные контрпримеры**
«так не надо» — в `language/pitfalls.md`, `tutorials/02`, `tutorials/03`,
`.github/pull_request_template.md`. Это ожидаемо, не «исправляйте» их.

Сам диалект, чтобы узнавать его в чужом коде: секции `function` / `input:` /
`output:` / `var:` / `begin:`, операторы `end_if`, `end_for`, `elsif`,
циклы `for i = 0 to n do`, индексация с нуля, `==` и `!=`,
вызовы `getStepSize()` / `getCurrentTime()` / `getParameter()`.

## Работа с фактами

Библиотека собирается из практики эксплуатации SimInTech, а не из пересказа
справки. Правила:

- **Не выдумывайте** имена блоков, свойств, функций и макро-команд. Если факт
  не подтверждён — опустите его или пометьте как непроверенный.
- В `blocks/*.md` таблица «Параметры» содержит **реальные имена свойств**.
  Сверяйтесь с каталогом `simintech_api/data/block_catalog.json` — он источник
  истины. Подтверждены работой через COM-интерфейс, например: `Константа` → `a`,
  `Сумматор` → `a`, `Интегратор` → `k` / `x0`, `Ступенька` → `t` / `y0` / `yk`,
  `Усилитель` → `a`); там, где подтверждения нет, стоит явное предупреждение.
  Сохраняйте это различие.
- **Расширения `.prj` у проектов SimInTech нет.** Проект — `.prt` (бинарный)
  или `.xprt` (XML). Если встретите `.prj` — это ошибка.
- **Не выдумывайте горячие клавиши.** В репозитории уже была заведена
  неверная пара «F9 — кодогенерация»: кодогенерация вызывается через
  «Инструменты» → «Сгенерировать программу», и такой клавиши не существует.
  Горячие клавиши в справке описаны фрагментарно и зависят от версии.
  Указывайте путь через меню как основной способ, а сочетание клавиш —
  только если оно подтверждено. Официальный источник для сверки:
  <https://help.simintech.ru/>
- **Официальная справка — <https://help.simintech.ru/>.** Она обновляется
  вместе с продуктом; при расхождении с этим репозиторием права она.
- Не переносите в публичный репозиторий сведения о внутренней инфраструктуре
  организаций: адреса, учётные данные, названия заказчиков, выдержки из
  закрытых технических заданий.

## Процесс

Ветка `main` защищена: прямой push запрещён, изменения идут только через
pull request (см. `.github/`). Требуется одно ревью. Для администратора
репозитория включён обход защиты — он может смержить свой PR без второго
ревьюера и запушить напрямую; строгость защиты на него не распространяется.
Скрипт `scripts/setup-branch-protection.sh` повторно применяет настройки
защиты — он же служит их документацией.

При написании нового материала:

- новый блок — отдельный файл в `blocks/<категория>/` по шаблону из `CONTRIBUTING.md`;
- заголовок файла — на русском, английский термин в скобках;
- кодировка UTF-8, переводы строк LF, финальный перевод строки;
- раздел «Предостережения» — это конкретные грабли с симптомом и решением
  (насыщение, алиасинг, размер шага, границы массивов), а не общие советы.
