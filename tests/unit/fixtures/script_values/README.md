# Значения `<script>` из настоящих выгрузок

Фикстуры здесь — **дословные значения**, снятые из файлов поставки SimInTech.
Обёртка `<page><name>…</name><script>ЗНАЧЕНИЕ</script></page>` собирается в
тесте: целиком элемент `<page>` весит 30 КБ (слои и блоки), а разбирается в нём
именно значение скрипта.

## Почему не рукописные

Первая версия тестов использовала придуманное `<script>``</script>` — форму,
которой в поставке **не встречается ни разу**: пустой скрипт пишется как
`<script></script>`, без кавычек. Регулярка, написанная под придуманную форму,
не совпадала ни с одной реальной страницей, и мост выбирал скрипт **чужой
страницы**. Тесты при этом были зелёными.

## Состав

| Файл | Откуда | Что показывает |
|---|---|---|
| `with_operators.txt` | `key_test.xprt`, значение `<script>` страницы `Container` | операторы `<` и `>` кодируются как `#60` и `#62`; коды стоят **вне** обратных кавычек |

```
`Line2.Visible = u `#60` 0.5`#13#10`Line3.Visible = u `#62` 0.5`
```

## Сплошная проверка

Единичный фрагмент доказывает мало, поэтому рядом живёт проверка под маркером
`distribution` (`test_script_probe.py`): она проходит по всем `.xprt` поставки и
требует, чтобы разбор покрывал значение целиком. На 1181 скрипте из девяти
файлов непокрытого остатка нет.
