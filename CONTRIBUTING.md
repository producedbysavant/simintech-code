# Contributing to SimInTech Code Library

Спасибо за интерес к проекту! Мы строим первую открытую библиотеку кода для SimInTech, и каждый вклад ценен.

## Процесс

Ветка `main` защищена: прямой push в неё запрещён для всех. Изменения проходят
только через pull request.

1. Найдите или создайте issue — шаблоны открываются автоматически.
   Для правки документации подойдёт «Ошибка в документации», для нового
   материала — «Новый материал».
2. Форкните репозиторий (или создайте ветку, если вы участник проекта):
   `git checkout -b docs/123-short-description`
3. Внесите изменения.
4. Убедитесь, что примеры кода соответствуют `language/syntax.md` — см. раздел
   «Синтаксис» ниже.
5. Создайте pull request, укажите в описании `Closes #<номер issue>` и
   отметьте чек-лист в шаблоне.

Для участников со статусом администратора требование ревью не блокирует
слияние, но проходить через PR нужно всё равно: так сохраняется история
обсуждений.

## Синтаксис

**`language/syntax.md` — источник истины.** Если пример ему противоречит,
прав пример, а не окружающий текст. Основное:

- Объявления плоские, каждое с явным типом: `input u: double;`, `var y: double;`.
  Запись `var a, b, c: double;` недопустима.
- Тело — `begin ... end`. Условие — `if ... then ... else ...;`.
  Цикл — `for (idx = 1, N) do begin ... end;`.
- Сравнения — `=` и `<>`, не `==` и `!=`. Логика — `and`, `or`, `xor`;
  оператор `not` не поддерживается, отрицание записывается сравнением.
- Массивы только статические, индексация **от 1**.
- Системные переменные — `time` и `hmax`/`hmin`, не `T` и не `dt`.
- Имена `i`, `j`, `c` использовать нельзя.
- Примеры кода помечайте как ```` ```simintech ````.

⚠ В репозитории ещё остаются файлы, написанные в старом диалекте
(секции `input:`, `end_if`, `getStepSize()`, индексация с нуля). Не копируйте
их стиль — при правке переводите код на канон.

## Как можно помочь

### 1. Добавить документацию блока

Если вы разобрались с блоком, которого нет в библиотеке — напишите документацию по шаблону:

```markdown
## Назначение
## Входы и выходы
## Параметры
## Пример схемы
## Код (если применимо)
## Предостережения
```

В разделе «Параметры» указывайте **реальные имена свойств** блока. Если имя
не удалось проверить на живой сборке — так и напишите, это лучше, чем
правдоподобная догадка.

### 2. Исправить ошибку

Нашли неточность? Создайте issue или PR с исправлением. Особенно важны:

- Неправильные имена параметров и свойств блоков
- Ошибки в формулах
- Некорректный код на встроенном языке
- Примеры, которые не проходят кодогенерацию (F9)

### 3. Добавить пример

У вас есть работающая модель, которую вы хотите показать сообществу? Добавьте
её в `patterns/`, `tutorials/` или `automation/`.

### 4. Перевод

Если вы хотите перевести документацию на другой язык — создайте issue
с обсуждением структуры.

## Стайлгайд

- Язык: русский (термины и код — английские)
- Каждый блок — отдельный `.md`-файл
- Заголовок файла: `# Блок «Сумматор» (Sum)` — русское название, английский
  термин в скобках
- Код на встроенном языке SimInTech должен быть рабочим
- Примеры схем — в виде ASCII-схем или описания связей между блоками
- Кодировка UTF-8, переводы строк LF (см. `.editorconfig`)
- Предостережения пишите конкретно: симптом, причина, что делать. Общие
  фразы вроде «будьте внимательны» бесполезны

## Что не принимается

- Реклама коммерческих продуктов
- Непроверенная информация, поданная как факт
- Спам
- Материалы, содержащие сведения о внутренней инфраструктуре организаций:
  адреса, учётные данные, названия заказчиков, выдержки из закрытых
  технических заданий
