# Типичные ошибки в SimInTech и их решения

Сборник распространённых проблем, с которыми сталкиваются пользователи SimInTech, и способы их решения.

## 1. «Программа не компилируется»

### 1.1. Пропущена точка с запятой

**Ошибка:**
```simintech
y = a + b   // забыта ;
z = c + d;
```

**Решение:** Каждый оператор должен заканчиваться `;`.

### 1.2. Несоответствие end

**Ошибка:**
```simintech
if x > 0 then
  y = 1;
// забыт end_if;
```

**Решение:** Каждый `if` завершается `end_if;`, каждый `for` — `end_for;`, каждый `while` — `end_while;`.

### 1.3. Регистр ключевого слова

**Ошибка:**
```simintech
If x > 0 then   // If, а не if — неверно
```

**Решение:** Все ключевые слова пишутся строчными буквами: `if`, `then`, `else`, `for`, `while` и т.д.

### 1.4. else if вместо elsif

**Ошибка:**
```simintech
if x > 0 then
  y = 1;
else if x < 0 then   // синтаксическая ошибка
  y = -1;
end_if;
```

**Решение:** Используйте `elsif` (одно слово):
```simintech
if x > 0 then
  y = 1;
elsif x < 0 then
  y = -1;
end_if;
```

## 2. Ошибки времени выполнения

### 2.1. Деление на ноль

**Проблема:** `y = 1.0 / x` при `x = 0` даёт Inf или ошибку.

**Решение:**
```simintech
if abs(x) > 1e-10 then
  y = 1.0 / x;
else
  y = 1e10;  // или другое разумное значение
end_if;
```

### 2.2. Переполнение интегратора

**Проблема:** Интегратор накапливает ошибку и уходит в бесконечность.

**Симптомы:** На графике — линейно растущий сигнал, который не останавливается.

**Решение:**
- Добавьте ограничение выхода интегратора
- Используйте анти-windup в регуляторах
- Проверьте, нет ли постоянной составляющей на входе

```simintech
state = state + u * dt;
if state > maxState then
  state = maxState;
elsif state < -maxState then
  state = -maxState;
end_if;
```

### 2.3. Выход за границы массива

**Ошибка:**
```simintech
double arr[5];
arr[5] = 10.0;  // индекс 5 вне диапазона [0..4]
```

**Решение:** Индексы массива от 0 до N-1. Проверяйте границы:
```simintech
int idx = 5;
if idx >= 0 and idx < 5 then
  arr[idx] = 10.0;
end_if;
```

### 2.4. Нарушение скважности при генерации импульсов

**Проблема:** Прямоугольный сигнал имеет неправильную скважность из-за округления.

**Решение:** Используйте остаток от деления с плавающей точкой:
```simintech
double t = getCurrentTime();
double period = 1.0 / frequency;
double phase = t - floor(t / period) * period;  // ручной mod
```
В SimInTech есть встроенный `mod` для double, но его поведение для отрицательных чисел может отличаться от ожидаемого.

## 3. Ошибки моделирования

### 3.1. Расходящееся решение

**Проблема:** Система «взрывается» — значения уходят в бесконечность.

**Причины:**
- Шаг моделирования слишком велик для данной системы
- Система неустойчива (полюса в правой полуплоскости)
- Положительная обратная связь вместо отрицательной
- Неправильный метод интегрирования для жёсткой системы

**Решение:**
1. Уменьшите шаг моделирования в 10 раз
2. Проверьте знаки обратных связей
3. Для жёстких систем используйте неявные методы интегрирования
4. Проверьте устойчивость системы (корни характеристического уравнения)

### 3.2. Некорректные начальные условия

**Проблема:** В начале моделирования система ведёт себя нефизично (рывки, выбросы).

**Причина:** Начальные условия интеграторов не соответствуют установившемуся режиму.

**Решение:**
- Рассчитайте начальные условия из уравнений установившегося режима
- Используйте секцию `init` для задания начальных состояний
- Добавьте «мягкий старт» — плавное нарастание уставки

```simintech
init:
  state = 0.0;
  prevU = 0.0;
  prevY = 0.0;
```

### 3.3. Алиасинг (ложные частоты)

**Проблема:** На графике отображается сигнал с частотой, которой нет в системе.

**Причина:** Частота сигнала выше половины частоты дискретизации (теорема Котельникова).

**Решение:**
- Уменьшите шаг моделирования (dt < 1 / (2 * f_max))
- Добавьте антиалиасинговый фильтр на входе

### 3.4. Жёсткая система (stiff system)

**Проблема:** Явный метод Эйлера требует нереально малого шага.

**Признак:** При любом разумном шаге решение расходится, хотя система должна быть устойчивой.

**Решение:** Используйте неявный метод Эйлера или метод трапеций.

```simintech
// Неявный Эйлер для звена 1-го порядка:
// dy/dt = (K*u - y) / T
// y[n+1] = y[n] + dt * (K*u - y[n+1]) / T
// y[n+1] = (y[n] + K*u*dt/T) / (1 + dt/T)

state = (state + plantGain * u * dt / plantTc) / (1.0 + dt / plantTc);
```

## 4. Ошибки подключения блоков

### 4.1. Циклическая связь без интегратора

**Проблема:** SimInTech выдаёт ошибку «алгебраическая петля» (algebraic loop).

**Причина:** Сигнал проходит через цепочку блоков и возвращается на вход без задержки (интегратора).

**Решение:**
- Добавьте интегратор в контур обратной связи
- Или добавьте блок «Задержка» (Unit Delay) в дискретных системах
- Используйте специальный блок «Разрыв обратной связи»

### 4.2. Неподключенные входы

**Проблема:** Блок выдаёт неожиданные значения.

**Причина:** Некоторые входы не подключены, но используются в расчёте.

**Решение:** Явно подключайте константу 0 к неиспользуемым входам или проверьте документацию блока — некоторые входы опциональны.

### 4.3. Несоответствие типов портов

**Проблема:** Связь не устанавливается.

**Причина:** Попытка соединить выход double со входом int (или наоборот) без явного преобразования.

**Решение:** Используйте блоки преобразования типов или убедитесь, что типы совместимы.

## 5. Ошибки логики

### 5.1. Интегральное насыщение (windup)

**Проблема:** После выхода из ограничения регулятор долго «приходит в себя».

**Причина:** Интегральная составляющая продолжает накапливаться, пока выход ограничен.

**Решение:** Останавливайте интегрирование при насыщении:
```simintech
if not saturated then
  integral = integral + error * dt;
end_if;
```

### 5.2. Дребезг (chattering) релейного регулятора

**Проблема:** Релейный регулятор переключается с частотой шага моделирования.

**Решение:** Добавьте гистерезис:
```simintech
if u > threshold + hysteresis/2.0 then
  y = 1.0;
elsif u < threshold - hysteresis/2.0 then
  y = 0.0;
end_if;
```

### 5.3. Неправильная приоритетность операций

**Проблема:** `y = a + b * c` вычисляется как `a + (b * c)`, а ожидалось `(a + b) * c`.

**Решение:** Явно используйте скобки: `y = (a + b) * c`.

## 6. Проблемы с производительностью

### 6.1. Моделирование идёт слишком медленно

**Причины:**
- Слишком малый шаг моделирования
- Слишком много блоков
- Активна запись всех сигналов в файл
- Включена анимация схемы

**Решение:**
- Увеличьте шаг моделирования (в разумных пределах)
- Отключите запись промежуточных сигналов
- Отключите визуализацию (режим без графики)
- Используйте более простую модель для предварительных расчётов

### 6.2. Файл данных слишком большой

**Причина:** Записываются все сигналы на каждом шаге.

**Решение:**
- Увеличьте шаг записи (каждый 10-й или 100-й шаг)
- Записывайте только нужные сигналы
- Используйте прореживание (decimation)

## 7. Ошибки в работе с матрицами

### 7.1. Неправильная размерность матриц

**Проблема:** При перемножении матриц размерности не совпадают.

**Решение:** Проверяйте: `A[m x n] * B[n x p] = C[m x p]`.

### 7.2. Использование неинициализированных массивов

**Ошибка:**
```simintech
var:
  double arr[10];
begin:
  y = arr[0];  // arr[0] содержит мусор
```

**Решение:** Инициализируйте массивы в секции `init`.

## 8. Ошибки округления

### 8.1. Сравнение double с нулём

**Ошибка:**
```simintech
if x == 0.0 then  // может не сработать из-за погрешности
```

**Решение:**
```simintech
if abs(x) < 1e-9 then  // близость к нулю
```

### 8.2. Накапливание погрешности

**Проблема:** При длительном моделировании погрешность интегрирования накапливается.

**Решение:**
- Используйте метод Рунге-Кутты вместо Эйлера
- Периодически сбрасывайте состояние (если позволяет физика процесса)
- Используйте double вместо float (в SimInTech double по умолчанию)

## Чек-лист перед запуском модели

- [ ] Все блоки подключены (нет мигающих портов)
- [ ] Нет алгебраических петель
- [ ] Шаг моделирования адекватен наименьшей постоянной времени
- [ ] Начальные условия интеграторов соответствуют физике
- [ ] Ограничения выходов установлены
- [ ] Анти-windup включён (где нужно)
- [ ] Знаки обратных связей правильные
- [ ] Метод интегрирования соответствует типу системы
- [ ] Время моделирования достаточно для переходного процесса
- [ ] Файл данных не переполнит диск
