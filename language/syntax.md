# Синтаксис языка SimInTech

Код блока «Язык программирования» исполняется на каждом расчётном шаге.
Блоки транслируются в C — код должен быть пригоден для кодогенерации.

## Ключевые слова

| Ключевое слово | Назначение | Пример |
|---------------|------------|--------|
| `input` | Входная переменная блока | `input u: double;` |
| `output` | Выходная переменная блока | `output y: double;` |
| `const` | Константа | `const g = 9.81;` |
| `var` | Переменная (сохраняется между шагами) | `var counter: integer;` |
| `begin..end` | Блок кода | `begin ... end;` |
| `finalization` | Секция завершения расчёта | `finalization ... end;` |

## Структура программы

Объявления идут до тела расчёта, в таком порядке: входы → выходы → константы →
переменные → подпрограммы. Тело расчёта выполняется каждый шаг; необязательная
секция `finalization` — один раз по окончании расчёта.

```simintech
input u: double;
output y: double;
const K = 2.5;

var state: double;

begin
    state = state + u * stepsize;
    y = K * state;
finalization
    // закрыть файлы, выгрузить накопленные данные
end;
```

`finalization` — единственное место, где уместны операции, которые нельзя
повторять на каждом шаге: запись итогового лога, закрытие файла, освобождение
ресурсов.

## Правила

- `;` — конец оператора
- `{ }` — блочный комментарий
- `//` — комментарий до конца строки
- Идентификаторы: латиница + кириллица + цифры + `_`
- **Регистр НЕ различается**: `Speed` = `speed`
- **Каждая переменная с явным типом**: `var a: double, b: double;`
- **Запрещены имена `i`, `j`, `c`** — конфликтуют с авто-счётчиками транслятора

## Типы данных

| Тип | Описание | Кодогенерация |
|-----|----------|---------------|
| `double` | Вещественное число (64 бит) | ✅ |
| `integer` | Целое число | ✅ |
| `boolean` | Логическое значение | ✅ |
| `array` | Массив вещественных чисел | ✅ (только статический) |
| `intarray` | Массив целых чисел | ✅ (только статический) |
| `string` | Строка | ❌ |

Объявление массивов:
```simintech
const MAX = 100;
var
    R[MAX]: array,
    indices[MAX]: intarray;
```

## Операторы

Арифметические: `+ - * /` и `div` (целочисленное), `mod` (остаток)
Сравнения: `= <> < > <= >=` (НЕ `==`, НЕ `!=`)
Логические: `and or not xor`

### О записи условий

Оператор `not` **поддерживается** и работает при кодогенерации в C. Но есть
рекомендация — формулировать условия в утвердительной форме. Правило называют
**принципом позитивного программирования** или правилом устранения двойного
отрицания; в литературе по чистому коду это «Invert Conditions» и
«Simplifying Conditional Expressions».

Причина — ментальная нагрузка. Двойное отрицание человек разбирает медленнее
и чаще ошибается: `if not isNotValid then` приходится мысленно переворачивать,
тогда как `if isValid then` читается сразу.

```simintech
// Читается хуже — двойное отрицание
if not (mode <> MODE_IDLE) then ...

// Читается лучше — утверждение
if mode = MODE_IDLE then ...
```

Это именно рекомендация, а не ограничение языка: простое одиночное отрицание
вроде `if not ready then` совершенно нормально, если утвердительная форма
выходит громоздкой. Ограничение касается вложенных отрицаний.
Битовые: `shl shr`

## Управляющие конструкции

```simintech
if x > 0 then
begin
    y = sqrt(x);
end
else
begin
    y = 0;
end;
```

```simintech
for (idx = 1, N) do
begin
    arr[idx] = idx * stepsize;
end;
```

```simintech
while error > tolerance do
begin
    error = error * 0.5;
    iter = iter + 1;
    if iter >= 50 then break;
end;
```

## Встроенные функции

`sin cos exp ln sqrt abs sign mod`
`min max sum mean round floor ceil trunc`
`lengthofm` — длина массива; `length` — длина строки

**Имена тригонометрии здесь не те, что в C.** Тангенса, арксинуса,
арккосинуса и арктангенса под привычными именами нет: в справке они
называются `tg`, `ctg`, `arccos`, `atan2`. Прежняя редакция этого раздела
объявляла встроенными `tan asin acos atan log10 pow size` — по реестру функций
справки (907 функций) таких имён в языке нет вовсе, включая `size`.

**Осторожно с двумя именами: в справке они с кириллической буквой.**
Страницы `arсsin` и `arсtg` записаны с кириллической «с» (`U+0441`) вместо
латинской `c` — проверено по байтам заголовка страницы, это дефект справки.
Имя, скопированное оттуда, в скрипт не встанет, а набранное латиницей не
найдётся точным поиском; поэтому `find_function` терпим к таким двойникам и
возвращает запись, в поле `name` которой видно настоящее написание.

Реестр — `simintech_api/data/language_functions.json`, поиск по имени:
`simintech_api.language.find_function`.

Файловые операции: `createfile`, `fileexists`, `seek`, `filesize`, `writelnutf8`.
Строковые: `strcopy`, `pos`, `lowercase`, `floattostr`.

## Пользовательские функции и процедуры

Поддерживаются `function`/`procedure` (см. webhelp «Подпрограммы»):

```simintech
function SumQ(A, out R: integer): double
    SumQ = sqr(A);        // возврат — присваивание имени функции
    R = round(SumQ);
end;
```

- Внутренние переменные функции при стандартном вызове **общие для всех вызовов**; для отдельных — модификатор вызова `|inline`.
- Выходные параметры декларируются словом `out`.

## Системные переменные (read-only)

| Переменная | Тип | Описание |
|------------|-----|----------|
| `time` | double | Текущее время моделирования (сек) |
| `stepsize` | double | Текущий шаг расчёта (сек) |
| `goodstep` | boolean | Признак «хорошего» шага: `true`, если расчёт выполнен в конце шага интегрирования и заданная точность достигнута |

`stepsize` — то, что нужно в подавляющем большинстве случаев: явный метод
Эйлера, дискретные фильтры, таймеры. `goodstep` нужен в редких блоках,
которые обязаны обновлять состояние только на «хорошем» шаге.

> ⚠ **`hmax` и `hmin` — не переменные языка.** Это параметры расчёта
> (настройки проекта, закладка «Параметры расчёта»): ограничение сверху
> и снизу на шаг интегрирования, по умолчанию 0.25. Обращаться к ним
> из кода блока нельзя — текущий шаг даёт `stepsize`.
>
> Ранее в этом документе `hmax` был указан как системная переменная — это
> было ошибкой. Если в вашем коде есть `hmax`, замените его на `stepsize`.

> ⚠ Переменные `T`, `dt`, `Nstep`, `Tstop` системными **не являются** (ошибочно указаны в ранних версиях этого документа). Полный перечень системных переменных — в официальной справке: <https://help.simintech.ru/>, раздел «Язык программирования SimInTech → Переменные → Системные переменные».

## Важные замечания

1. Код выполняется на каждом шаге — не используй бесконечные циклы
2. `var` сохраняет значение между шагами (в отличие от интерпретатора)
3. Размерности массивов фиксированы — избегай динамических массивов
4. Нет динамической памяти
5. После изменений запускай кодогенерацию — «Инструменты» → «Сгенерировать
   программу» — и разбирай сообщения в окне вывода
6. `#`, `&`, `..` не транслируются в C — используй циклы
