# 06. Скриптовый мост: протокол, жизненный цикл, ошибки, восстановление

Раздел базы знаний (индекс — `README.md`). Мост — самая защищённая часть
библиотеки: он даёт то, чего COM не умеет (чтение скриптов, выгрузка
топологии, исполнение тел), и стоит там, где ошибка среды не сообщается
никак. Реализация — `simintech_api/core/script_bridge.py` и
`script_probe.py`; MCP-надстройка — `simintech-mcp/tools/page_script.py`
(контурное ядро `run_contour`).

## Контракт (почему всё так сложно)

Факты, из которых собран мост:

| id | Факт | Статус |
|---|---|---|
| `setpagescript-returns-one-always` | `SetPageScript` возвращает 1 и при неверном скрипте; прежний скрипт затирается | live-verified |
| `script-compile-errors-are-silent-via-com` | Ошибки компиляции через COM невидимы (текст — в окне редактора) | live-verified |
| `floating-input-stops-calculation` | Неподключённый вход останавливает расчёт молча — «время не растёт» двусмысленно | live-verified |
| `no-getpagescript-in-com-api` | Чтения скрипта страницы в COM нет | code-confirmed |
| `page-init-reruns-on-each-step` | На несчитающей модели каждый `ProjectStep` переисполняет `initialization` | live-verified |
| `run-outruns-the-first-time-read` | Считающая модель проходит остаток до `endtime` за доли секунды: база времени читается **до** `ProjectRun` | live-verified |
| `projectstart-executes-init-and-resets-time` | `ProjectStart` исполняет `initialization` и сбрасывает время; `ProjectRun` из состояния 1 страницу не переинициализирует | live-verified |
| `endtime-run-executes-init-without-growth` | На проекте, дошедшем до `endtime`, голый `ProjectRun` исполняет `initialization` один раз без роста времени | live-verified |

Поэтому мост не верит ничему, что не может доказать: маркеры в файле
результата, рост времени, снимки скриптовых записей.

## Протокол контура (`run_page_script`)

1. **Опознание цели.** Отказ на ненулевом `GetProjectStateFlag` (чужой
   расчёт не уничтожаем); текущая страница — по `GetCurentPage`; до установки
   тела снимается выгрузка `SaveProjectXML` (скриптовые записи всех страниц);
   телу добавляется уникальная метка-комментарий. Метка уже есть в проекте →
   `ScriptBridgeUnsafeStateError` «проба не начата, проект не тронут».
2. **Тело — в `initialization`** (только там создаются объекты;
   `objects-are-created-only-in-initialization`). До тела пишется `CTX_BEGIN`,
   после — `CTX_END`.
3. **Запуск и ожидание.** Один `ProjectRun` (не шаговый цикл — тот
   переинициализировал страницу), опрос `GetProjectTime`; база — до запуска.
   Ранний выход по `CTX_END` + grace-окно (5 с — компромисс, названный в коде).
4. **Классификация исхода** по маркерам и времени (пять состояний):
   `ok` — оба маркера, время росло; `model-not-running` — оба, время стоит;
   `aborted` — есть begin без end (тело оборвалось, в ответе последняя
   записанная строка); `not-compiled` — маркеров нет и время стоит;
   `section-not-run` — маркеров нет, время росло.
5. **Уборка (`finally`):** остановка расчёта первой (никогда не бросает),
   затем возврат прежнего скрипта **в ту самую страницу**: страница
   опознаётся по единственной изменившейся записи с меткой
   (`bridge-identifies-its-page-by-snapshot`); сомнение — `UnsafeState`, а не
   возврат по догадке; расхождение длин сверяется по фактам (метка/текст) и
   попадает отдельным предупреждением.
6. **Результат** — файл результата в каталоге песочницы: строки тела
   возвращаются ответом; пара маркеров ровно одна; запертый файл (обрыв без
   `freeobject`) — `PermissionError` c названной причиной, имя контурного
   файла уникально на вызов (обход `WinError 32`).

## `fid` — приманка, а не дескриптор

Тело пишет строки через «дескриптор» `fid` — на деле это **приманка**:
настоящий дескриптор моста лежит под случайным именем. Чужой код, зовущий
вендорскую процедуру, присваивающую `fid` (например
`export_1layer_topology`), уводит приманку, а не дескриптор; после такого
кода писать — процедурой `br_writeln` (находит дескриптор сама). Живой тест
этого — `tests/integration/test_script_bridge_live.py:76`.

## Чтение скрипта без расчёта

`read_page_script` читает прежний скрипт **снимком** (`page-script-readable-without-calculation`):
ставит заглушку с меткой, снимает выгрузку, декодирует прежнюю запись,
возвращает на место. `ProjectStart` не зовётся вовсе — иначе обнулилось бы
модельное время и результаты вызывающего. MCP: `get_page_script`,
`get_block_script` (снимок), `set_page_script` (два шага: проверка компиляции
контуром → установка насовсем).

## Мост для правок (MCP-контур)

- Тела `run_page_script`/`set_block_script`/`set_block_size`/`remove_block`/
  `disconnect_wire`/`connect_branch`/импорт-экспорт текста идут через одну
  точку — `page_script.run_contour` (`mcp-contour-core-single-entry`).
- «Не сделано» не имеет права вернуться успехом: `refuse_contour_failure` —
  единственный маппер (`not-compiled`/`aborted`/`section-not-run` →
  `ToolError`; обрыв — с честным «нельзя утверждать, что не сделано»).
- «Читающие» контурные инструменты **перезапускают расчёт и сдвигают
  модельное время** (`mcp-contour-reads-shift-model-time`) — это цена моста,
  названная в докстрингах.

## Ограничения и открытые вопросы

- `floattostr(time)` в присвоенном скрипте записи не даёт; `finalization` при
  внешней остановке расчёта не срабатывает (замеры 2026-09-29) — данные
  собираются записью на каждом шаге.
- Инжектированной субмодели скрипт компилируется только с `reinitsubmodel`
  (`submodel-script-injection-needs-reinitsubmodel`).
- Пробелы раздела 10: `load_submodel`/`assign_submodel`, рестарт-группа,
  `Pack.run_to` — живьём не проверялись.
