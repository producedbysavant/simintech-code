# 04. Каталог блоков и свойства: откуда брать точные имена

Раздел базы знаний (индекс — `README.md`). Отвечает на вопрос «где взять
правильное имя параметра» и какие источники имён **не являются** точными.

## Источник истины — каталог, и только он

`simintech_api/data/block_catalog.json` — 958 классов, ~8700 записей имён
свойств, собран генератором по живому SimInTech
(`simintech-generate-catalog`, раздел «Команды» в `CLAUDE.md`). Имена
короткие и неочевидные: у «Константы» — `a` (не `y0`), у «Сумматора» — `a`
(веса входов), у «Интегратора» — `k`/`x0`.

Почему это критично: **`SetBlockProp` не отвергает неизвестное имя** — запись
проходит без ошибки и ни на что не влияет (`setblockprop-ignores-unknown-name`).
Компенсация — сверка имён по каталогу **до** записи: библиотечный
`catalog.check_params` и MCP-инструменты `add_block`/`set_block_param`
(отказ со списком известных имён, `allow_unknown` — осознанный обход).

| id | Факт | Статус |
|---|---|---|
| `constant-param-is-a` | У «Константы» значение задаётся `a`; `y0` не существует | live-verified |
| `summator-ports-need-setportcount` | Длина массива `a` входы не добавляет: число портов меняет `SetPortCount` | live-verified |
| `fsm-blocks-need-full-record-name` | Блоки «Конечные автоматы» создаются только по полному имени записи («Конечные автоматы - Состояние автомата»); короткий заголовок с палитры не принимает `CreateBlock` | live-verified |

## Что точным источником имён НЕ является

| Источник | Почему нельзя | Что там вместо правильного |
|---|---|---|
| `blocks/*.md` (этот репозиторий) | Рукописные описания, часть — из чужого диалекта | встречаются `value`/`signs`/`numInputs` против реальных `a`/`y0`/`k` |
| `examples/` | Примеры пишутся раньше замеров и отстают | устаревшие имена |
| Справка вендора (в части свойств) | Описывает намерение, а не факт конкретной сборки | — |
| Другие модели (`export_model_text` чужого проекта) | Имя экземпляра ≠ имя параметра | данные, не схема |

Правило скиллов (`simintech-skill/README.md`): имена свойств берутся из
каталога; `blocks/*.md` улучшаются, но пересказу не верят.

## Провенанс каталога: что известно и что нет

| id | Факт | Статус |
|---|---|---|
| `catalog-provenance-unknown` | `meta.observation.observed_at`/`dump_sha256` у закоммиченного файла — `unknown` (прогон генератора дату не записал, выгрузка не сохранена) | unknown |
| `catalog-failed-classes-not-created` | 156 классов помечены `failed`: среда их создать не смогла (нелицензированные модули и подобное) | code-confirmed |
| `block-size-covers-few-classes` | `standard_block_size` знает размеры лишь части классов; остальным размер не подменяется | live-verified |

**Следствие.** «Класс есть в каталоге» ≠ «набор имён полон»: покрытие имён
последний раз мерилось 17.09.2026 (848 из 1039 под проверкой, состояние
`docs/gap-closure-plan.md`, Н1). Догрузка идёт из живого SimInTech — см.
план в разделе 10 (пересборка с полным `observation`).

## Каталог vs классы-конструкты

- Классы с конструктивными особенностями: «Из памяти» создаётся, но прямой
  `CreateBlock` отдаёт его **без портов** — порт настраивается
  `PortNames` + `initobject` (`createprimitiv-object-has-no-ports` — та же
  механика для объектов языка).
- «Порт выхода» отвергается `add_block` политикой allowlist библиотеки, но
  импортом текста создаётся и в расчёте годен (замеры 08.10.2026) — см.
  актуальные формулировки в скилле `simintech-model-building`.
- Класс субмодели в тексте — `type = "Субмодель"` (не `Macro`): `Macro`
  `createmodel` молча игнорирует (вердикт `ok`, объектов ноль; замеры
  06–10.10.2026).

## Практическая процедура

1. Имя параметра — из каталога (`MCP: get_block_params` / ресурс
   `simintech://blocks/catalog`).
2. Запись — `set_block_param`/`add_block` (сверка до COM). Параметр, которого
   в каталоге нет, а в блоке есть — `allow_unknown=True` **осознанно** и с
   последующей догрузкой каталога.
3. Размер блока — не параметр: `set_block_size` (языковая пара
   `setpropformula` + `setprop` — «Значение», не «Формула»), у порт-блоков
   высота подчинена правилу 16 px на строку (раздел 05).
