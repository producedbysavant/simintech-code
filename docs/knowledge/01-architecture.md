# 01. Карта архитектуры и ответственности репозиториев

Раздел базы знаний (индекс — `README.md` этого каталога). Отвечает на вопрос
«где что живёт и кто за что отвечает» — коротко и по факту, без пересказа
README каждого репозитория.

## Три репозитория и их роли

| Репозиторий | Ответственность | Потребитель |
|---|---|---|
| `simintech-code` — библиотека `simintech-api` | Вся работа с COM (`IMVTU_Server`, `mmain.exe`), скриптовый мост, топология, раскладка, каталоги (блоков и языка), форматы файлов, CLI-путь; **плюс** доказательная система (`docs/evidence/`) и эта база знаний | MCP-сервер, Python-скрипты пользователя |
| `simintech-mcp` — MCP-сервер | Предъявить SimInTech агенту: 59 инструментов, 8 ресурсов, 2 промпта; сессия (клиент/проект/пакет/линии), контракт отказа, песочница чтения, контурное ядро | Claude Code и другие MCP-клиенты |
| `simintech-skill` — доменные знания | Скиллы агента: язык, сборка модели, расчёт, каталог, скрипт блока; гейты сверяют пересказ с машинными источниками | агент (через ресурсы MCP и Claude Code Skills) |

Связи: MCP-сервер зависит от библиотеки по **релизному тегу с якорем**
(`simintech-mcp/pyproject.toml`; политика 2026-10-01: теги `v*` неизменяемы
ruleset'ом, `scripts/check_pins.py` сверяет якорь и `__version__`).
Скиллы цитируют данные библиотеки и проверяются её же тестами
(`SIMINTECH_CODE_DIR` в CI скиллов).

## Где источник истины (для каждого класса вопросов)

| Вопрос | Источник истины | Как проверяется |
|---|---|---|
| Сигнатуры и наличие методов COM | `docs/reference/com_api_inventory.md` + код `core/` | инвентарь с пометками замеров; мост и клиент |
| Функции встроенного языка | `simintech_api/data/language_functions.json` (срез справки) | генератор `python -m simintech_api.language <webhelp>`; гейт свежести |
| Имена параметров блоков | `simintech_api/data/block_catalog.json` | генератор по живому SimInTech + `simintech-mcp` сверяет имена до записи |
| Факты о поведении среды | `docs/evidence/claims.yaml` (схема v3) | валидатор в CI; производные — `verification-matrix.md`, `contradictions.md` |
| Синтаксис языка | `language/syntax.md` (канон) + `language/pitfalls.md` | примеры в `examples/`; расхождение — прав пример |
| Раскладка (канон ТЗ 4.2–4.4) | `simintech_api/layout/canon.py` | юнит-тесты; сверка снимком на боевых моделях |
| Контракт MCP-поверхности | `simintech-mcp/tests/unit/test_surface.py` | исполняемый: декораторы, наборы, README-числа |

**Правило проекта:** источник истины — машинный (код, сгенерированный файл,
замер с провенансом). Документ-пересказ (`blocks/*.md`, README, скиллы)
истиной не является — и именно поэтому база ссылается на id реестра, а не
пересказывает замеры заново.

## Как ходят данные (сквозная цепочка)

1. **Сборка модели:** MCP-инструмент → библиотечный объект (`Project`, `Page`,
   `Block`) → COM (`CreateBlock`, `CreateWire`) либо языковой текст
   (`createmodel` через контур). Импорт текста описан в разделе 06 и в
   записях реестра о запечённой геометрии.
2. **Чтение того, чего COM не отдаёт** (концы линий, скрипты, топология):
   только скриптовый мост (`savemodeltofile`, пробы) — раздел 06.
3. **Расчёт и результат:** `Simulation.run_to` (опрос времени, `RunTo` не
   блокирующий) → блок «В файл» → `read_output_file` (песочница MCP).
4. **Проверка вида:** снимок (`savescreenshot` через контур) — единственная
   проверка того, что нарисовано (разделы 6, 7).

## Процесс (соблюдать при любой правке)

- `main` всех трёх репозиториев защищён: PR обязателен, **каждый PR закрывает
  issue** (`Closes #N` первой строкой), один PR — одна тема, squash-мерж.
- Артефакты без версии и даты в базу не принимаются (правило
  `docs/knowledge-snapshot.md`: «артефакт без версии и даты — не знание,
  а воспоминание»).
- Правка поведения библиотеки — сначала в `simintech-code`, затем выпуск
  тега, затем подъём пина в `simintech-mcp` (`docs/compatibility-matrix.md`).
- Пробы и разведка в публичные репозитории не переносятся: сюда едет вывод с
  провенансом (см. `docs/gap-closure-plan.md`, «Как проверять»).
