# Единая база технических знаний экосистемы SimInTech

Назначение базы — **предотвращать ошибки разработчика и агента**: фиксировать
установленные факты о среде и библиотеке, границы применимости и открытые
вопросы так, чтобы «мы измерили» было неотличимо от «мы предполагаем» только
по желанию автора, а не по умолчанию.

База — это **слой над реестром**: машинный источник истины один —
`simintech-code/docs/evidence/claims.yaml` (схема v3). Тематические документы
пересказывают факты коротко и ссылаются на реестр по id; машина сверяет, что
каждый названный в таблицах id существует (`scripts/evidence.py`).

## Правила ведения (их держит валидатор)

1. **Статус присваивается источнику, а не тексту.** Словарь один:
   `documented` (официальная документация), `code-confirmed` (следует из
   кода), `live-verified` (живой прогон/опыт/наблюдение выгрузки),
   `vendor-confirmed` (поддержка или исходник вендора), `hypothesis`,
   `contradicted` (с обязательным `contradicted_by`), `unknown`.
2. **Производный документ не доказывает.** README, скиллы, журналы и эта
   база — пересказы; с источником `derived-doc` допустимы только
   `hypothesis`/`unknown`/`contradicted`. «Повторено в трёх документах» —
   не подтверждение.
3. **Тест на фейке не доказывает среду.** `unit-fake` фиксирует контракт
   кода; единственной опорой `live-verified` он быть не может.
4. **У «подтверждено» есть версия, дата и способ воспроизведения.**
   `environment` и `reproduction` обязательны для живых статусов.
5. **Опровергнутое не удаляется** — переводится в `contradicted` со ссылкой,
   чем опровергнуто: иначе через полгода вывод «починят» обратно.
6. **Непроверенное называется непроверенным.** Раздел 10 — не свалка, а
   очередь экспериментов; `unknown` без плана проверки — долг.

## Как добавить факт

1. Запись в `docs/evidence/claims.yaml` (id — kebab-case; формулировка —
   факт плюс граница применимости; при противоречии прежней записи — новый
   id и `supersedes`).
2. Строка в таблице подходящего раздела базы (первая колонка — `` `id` ``).
3. `python scripts/evidence.py` — валидатор и производные виды
   (`verification-matrix.md`, `contradictions.md`).
4. Тест или `reproduction`: у живого факта — хотя бы одно из двух.

## Чего в базе нет и не будет

- Справки по API блоков и языка «целиком» — для этого есть
  `blocks/*.md`, `language/*.md`, справка поставки и реестр функций;
- версий и планов «на будущее» — это `docs/roadmap-agentic-ecosystem.md`
  (журнал) и issue-очередь репозиториев;
- пересказа кода — факты должны отвечать на вопрос «что сломается, если
  этого не знать», а не «как устроен модуль».
