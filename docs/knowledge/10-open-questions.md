# 10. Реестр неподтверждённого и план исследований

Раздел базы знаний (индекс — `README.md`). Здесь живёт очередь экспериментов:
факты со статусами `unknown` и `hypothesis` из реестра
(`docs/evidence/claims.yaml`) и что с ними делать. **`unknown` без плана
проверки — долг:** каждый пункт ниже обязан иметь строку «чем закрыть».

## Открытые вопросы (из реестра)

| id | Вопрос | Чем закрыть | Приоритет |
|---|---|---|---|
| `catalog-provenance-unknown` | Провенанс `block_catalog.json`: `observed_at`/`dump_sha256` — `unknown` | Пересборка каталога на живом стенде (`simintech-generate-catalog`, `observation` заполняется сам) с записью версии и `--coverage` | P1 — от каталога зависят имена параметров |
| `savemodeltotext-missing-from-distribution` | Вендор называет 4 функции текста модели, в поставке видны 3; `savemodeltotext` не найдена | Поиск по активному каталогу справки и, при возможности, вопрос поддержке; пока — не опираться на имя | P1 — имя может уйти в сценарий |
| `project-restart-group-unverified` | Рестарт-группа `Project` (перезапуск проекта) | Живой прогон на тестовом проекте: состояние, время, файлы | P2 |
| `submodel-load-assign-unverified` | Различие `load_submodel` и `assign_submodel` | Живой прогон: оба пути, сверка состояния блока и страницы | P2 |
| `wire-branch-to-unverified` | `Wire.branch_to` не вызывается и не измерен | Живой прогон; сравнить с рабочим `connect_branch` MCP | P3 |
| `comclient-project-enumeration-unverified` | Перечисление открытых проектов в `COMClient` | Живой прогон с двумя открытыми проектами | P3 |
| `pack-run-to-semantics-unverified` | `Pack.run_to` → `WaitForTimePack`: что значит False | Живой прогон; ср. `packrun-does-not-advance-in-embedding` | P3 |

## Регулярные проверки (по событиям, а не по календарю)

| Событие | Что прогнать | Почему |
|---|---|---|
| Смена поставки SimInTech | Живой набор `tests/integration -m integration`; повторный замер фактов со `version-specific`-привязкой | Все `live-verified` привязаны к версии и дате; новая поставка может их снять |
| Подъём пина библиотеки в MCP | `test_dependency_contract`, живая приёмка MCP на голове | Сервер держит код ревизии запуска |
| Пересборка каталога | `--coverage`, обновить `knowledge-snapshot` | Покрытие имён — обязательство каталога |
| Правка моста | Живые тесты моста (`test_script_bridge_live.py`, `test_language_contour_live.py`) | Мост — единственный путь к скрытому; поломки тихие |

## Известные ограничения, зафиксированные как «не проверено» (не вопрос, а граница)

- **Порядок треков внутри канала** в аудите маршрутов — модель
  (`channel-track-order-is-model`); проверяется снимком, живой замер —
  только для дальней связи (`far-link-midpoint-vertical-live`).
- **Одноаргументная форма `traceallports`** живым прогоном не звалась
  (default подтверждён вендорским листингом —
  `traceallports-second-arg-defaults-true`).
- **`Point`-габарит подписей** и метрики снимка — по замерам 02–08.10.2026;
  на новой поставке подлежат перепроверке как обычные `live-verified`.

## Как заводить новый вопрос

1. Запись в реестр со статусом `unknown` (или `hypothesis`), источник —
   где вопрос живёт, `reproduction` — как проверить.
2. Строка в таблицу выше: чем закрыть и приоритет.
3. Когда проверка сделана — запись переводится в `live-verified` (или
   `contradicted`), строка переезжает в тематический раздел базы. Из списка
   удаляется только после этого — «стало неактуально» без замера не повод.
