# Скрипт субмодели, текст модели и удаление объектов: что измерено 2026-09-29

Дата: 2026-09-29. Поставка: SimInTech64 2.26.6.23 (`bin/mmain.exe` от 23.06.2026).
Живые прогоны через COM: скрипт страницы ставится `SetPageScript`
(`ScriptBridge.install_script`), расчёт — `ProjectStart` и `ProjectStep`.
Каждый прогон начинается с чистого состояния: перед ним снимаются **все**
найденные `mmain.exe`, после — свой процесс (иначе следующий прогон
подключается к прошлому и видит его объекты).

Документ дополняет `2026-09-28-wire-level-and-coports.md`: там — линии, порты и
границы контейнеров, здесь — субмодели со скриптом, семейство текста модели и
удаление объектов.

## 1. Что измерено

### 1.1. Присвоенный субмодели скрипт компилируется только после `reinitsubmodel`

Пример вендора `Инжектирование скрипта в пакет через субмодель` (папки с ним в
поставке 2.26.6.23 нет) присваивает субмодели скрипт динамически:

```pascal
objid = createprimitiv(102, [(0, 0), (-16, 0), (0, -16), (0, 16)]);
setprop(objid, "script", <текст>);
```

Замер: без третьего шага присвоенный скрипт **не компилируется и не
исполняется** — ни тело, ни `finalization`; файла-маркера нет, сообщений тоже.
Третий шаг обязателен:

```pascal
reinitsubmodel(objid);   // «переинициализация и компиляция скриптов субмодели»
```

| Проба | Что делает | Результат |
|---|---|---|
| без `reinitsubmodel` | присвоить и запустить расчёт | маркера нет (дважды: с `runproject` и без него) |
| без `runproject`, только присвоить | расчёт от внешнего клиента | маркера нет |
| с `reinitsubmodel` | то же | **тело исполняется на каждом шаге расчёта**, `seterrorstr` из примера вендора работает |

Ограничения внутри присвоенного скрипта (там же):

| Что | Результат |
|---|---|
| `writelnutf8(fw, "T=" + floattostr(time))` | файл создан, но **пуст** — обрыв на `time` |
| `seterrorstr("Time = " + time)` (формула вендора) | **компилируется и исполняется** — строки до и после вызова записаны |
| `finalization` при остановке расчёта извне (`sim.stop()`) | **не срабатывает**; при естественном окончании не проверено |

Вывод для практики: данные из присвоенного скрипта собирают записью в файл **в
теле**, а не в `finalization`; значение `time` тут считать нечем.

### 1.2. Порты субмодели: `initsubmodelports` делает их видимыми сразу

Прежнее наблюдение «внешние порты субмодели видны только с первого шага
расчёта» отменяется. `initsubmodelports(sub)` пересобирает порты по блокам
«Порт входа»/«Порт выхода» внутри субмодели:

| Шаг | `getblockportcount(sub)` |
|---|---|
| субмодель создана, оба порта добавлены на её страницу | 0 |
| `initsubmodelports(sub)` → 1 | **2** — ещё в `initialization` |

### 1.3. Удаление объекта: `removeprimitiv` работает, но роняет старт расчёта

Удаление объекта из скрипта работает: после `removeprimitiv(id)`
`findobjectbyname` возвращает `0`, счётчик контейнера уменьшается. Но
**следующий запуск расчёта** завершается аварийно: `ProjectStart` возвращает
`Access violation at address 000000006915E361 in module 'mbtylib.dll'.
Read of address FFFFFFFFFFFFFFFF`.

Изоляция — четыре прогона «удаление × выгрузка модели»; во всех скрипт
отрабатывает целиком (лог дописан до последней строки), падает именно старт:

| Прогон | Удаление | `savemodeltofile` | Старт расчёта |
|---|---|---|---|
| A | блок | есть | **падение** (воспроизведено дважды) |
| C | провод, затем блок | нет | **падение** |
| B | нет | нет | расчёт идёт |
| D | нет | есть | расчёт идёт |

Объекты создавались `createmodel` в `initialization` (два блока и провод).
Готовый воспроизводитель отправлен вендору 2026-09-29 (проект со скриптом
внутри + контрольный проект без удаления); в проекте вендора он открывается
как есть и падает по кнопке «Пуск».

### 1.4. Текст модели: кавычки — `chr(34)`, BOM не нужен, семейство работает

Прежний отрицательный результат по `createmodelfromfile` объяснён: наш текст
модели был невалиден из-за кавычек.

| Форма кавычки | Результат |
|---|---|
| `chr(34)` | текст принимается, объекты создаются |
| удвоение `""` | даёт **пустую строку** — объектов не появляется, сообщений нет |
| обратный слэш `\"` | **не экранирует** |

BOM: `createmodelfromfile` файл с BOM принимает, вклейка через `eval` — нет
(BOM попадает в исходник).

Все пять демонстрационных проектов `Demo/Язык программирования/Функции/Создание
схем из скрипта createmodel` проходят: `createmodel` (модель в скрипте),
`createmodelfromfile` (файл), `createmodel` через `eval` из файла,
`loadtextfromfile` и `savemodeltofile`. Приросты объектов совпали у
COM-прогонов и ручных прогонов владельца.

`savemodeltofile` подтверждён дополнительно: выгрузка идёт на всю глубину (два
и три уровня `subsystem:` подряд) и начинается со свойств страницы
(`x_center`, `y_center`, `x_scale`, `y_scale`, `script`).

### 1.5. Точка в имени: текст модели, а не язык скрипта

`object.property = value` из ответа вендора относится к **декларативному
тексту** модели (`a.formula = 10`, `x_center = …`). В языке скрипта точка в
выражении недопустима: компилятор отвечает
`[Предупреждение] (23): В имени локальной переменной точка недопустима:
dblock.a`, работа скрипта продолжается, присваивание не происходит
(замер: значение осталось прежним). Из скрипта параметры пишут
`setprop`/`setpropasstring`.

### 1.6. Обход контейнеров: имена и приёмы (по демонстрационным проектам вендора)

Иерархия читается не только выгрузкой текста. В демонстрационных проектах
вендора используются:

- обход **вниз** — `getsubmodelid(block)` → `getobjcount(contid)` →
  `for (i = 1, num)` `getobj(contid, i)` (индекс **с единицы**) плюс
  `getpropasstring(id, "ClassName")` для опознания класса объекта
  («Конечные автоматы», `Пример 0.prt`);
- подъём на уровень — `getownercontainer(obj)` → `submodelbypageid(page)` →
  `getfullname(block)` (пример
  `Demo/Приёмы работы/Получение данных, доступа и т. п./Получение имени
  субмодели через уровень при помощи submodelbypageid`);
- подъём по проводу — `getblockportid` → `findstartport` → `getportblockid` →
  `getownercontainer` → `submodelbypageid`.

Все семь имён есть в срезе справки (`simintech_api/data/language_functions.json`,
v15.05.2026): `getobj`, `getownercontainer`, `submodelbypageid`, `findstartport`,
`getportblockid`, `getfullname`, `getsubmodelid`.

## 2. Что уточнил вендор (2026-09-29)

Ответ технической поддержки вендора, 2026-09-29 (пять пунктов):

1. `createmodel` и `savemodeltofile` — стабильные, возможны опциональные
   аргументы, не влияющие на совместимость.
2. Удаление — `removeprimitiv`; `createmodel` генерирует поверх существующей
   модели: дополненные объекты добавятся, старые останутся.
3. Пример обхода в глубину есть в примерах; `savemodeltofile` по умолчанию
   читает на всю глубину.
4. `traceallports` сделан и меняться не будет.
5. Предложено прислать пример (отправлен 2026-09-29).

Отдельно вендор назвал инжектирование скрипта через субмодель и приём
«параметрировать уже созданную модель в штатном формате языка»
(`object.property = value`) — см. §1.1 и §1.5.

## 3. Что не измерено

- Срабатывает ли `finalization` присвоенного скрипта при **естественном**
  окончании расчёта (при внешней остановке — не срабатывает).
- Что возвращает `time` внутри присвоенного скрипта и как вывести его значение.
- Инжектирование **в пакет**: `getcurrentpackid` на проекте вернул `0`,
  `OpenPack` на нашей фикстуре — тоже `0`; нужен пакет из поставки или пример
  вендора.
- Повторный `createmodel` поверх существующей модели (вендор описывает
  поведение, мы его не мерили).
- Причина падения после `removeprimitiv`: воспроизведение и изоляция есть,
  локализация — нет.
