# Источники доказательств

Список того, откуда берутся утверждения реестра (`claims.yaml`). Записи реестра
ссылаются сюда через `source.ref`; здесь — что это за источник, на какой версии
и что именно из него следует.

**Иерархия доверия** (сверху вниз): живой прогон через COM → сверка с
поставкой → справка вендора → вывод из кода → предположение. Чем ниже
источник, тем важнее, чтобы это было видно в статусе утверждения.

| Источник | Тип | Версия / дата | Что из него следует |
|---|---|---|---|
| Живой COM (`mmain.exe /regserver`, Windows) | `live-com` | SimInTech64, поставка 2.26.6.23 | Поведение методов (`SetBlockProp`, `RunTo`, `CreateBlock`), состояние проекта, читаемость сигналов |
| Выгрузка проекта `.xprt` | `xprt-observation` | те же | Имена параметров (`custom_props`), наличие расчётного слоя, классы и имена блоков |
| Поставка SimInTech (`C:\SimInTech64`) | `source-code` | 2.26.6.23 | `export_sheme_functions.inc` (вендорский алгоритм связей), демо-проекты, каталог `.csl` |
| Справка SimInTech | `official-doc` | help.simintech.ru, срез v15.05.2026 | Синтаксис встроенного языка, состав функций, описание API |
| Контролируемые опыты | `controlled-experiment` | 2026-09-15 … 2026-09-23 | Сравнение вариантов: считает ли проект, растёт ли время, как ведут себя порты |
| Документы репозитория | `inference` | — | `docs/roadmap-agentic-ecosystem.md`, `docs/gap-closure-plan.md`, `docs/reference/com_api_inventory.md` — сводки замеров, не первоисточник |

## Почему это не «список литературы»

Реестр различает два вида знания, которые обычно смешаны в прозе:

- **подтверждено** (`verified`) — за утверждением стоит источник вне нашего
  кода: живой тест, сверка с поставкой или справка вендора;
- **измерено** (`measured`) — живой замер, записанный в документе; автотеста
  нет, и это честно указано.

Отдельно помечается `unit-only`: покрытие тестом на подделке. Такой тест
фиксирует контракт кода, но **не** подтверждает поведение среды — подделка
повторяет наше допущение и опровергнуть его не может. Без этого различия
«покрыто тестами» звучит как «проверено на SimInTech», хотя проверено на нашей
же выдумке.

## Обновление

Новый замер → запись в реестр с датой и версией → `python scripts/evidence.py`
(перегенерирует `verification-matrix.md`). Если замер противоречит прежней
записи, прежняя не удаляется: она переводится в `refuted` с текстом, чем
опровергнута, — иначе через полгода кто-нибудь «починит» вывод обратно.
