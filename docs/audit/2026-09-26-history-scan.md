# Разовый скан истории трёх репозиториев (2026-09-26)

Скан выполнен по трём репозиториям экосистемы после появления гейта
`scripts/public_data_check.py` (волна P1 плана
`docs/superpowers/plans/2026-09-26-ecosystem-hardening.md`).

**Как читать этот отчёт.** Здесь записано, что **найдено и как разобрано**, а
не «приватных данных нет»: отсутствие находок у сканера не является
доказательством отсутствия данных, а история git не становится чище от того,
что её перестали смотреть.

## Чем сканировали

| Инструмент | Что смотрит | Результат |
|---|---|---|
| `gitleaks` (`.gitleaks.toml`) | секреты, вся история | чисто (CI job `secrets` в трёх репозиториях) |
| `public_data_check.scan_text` | приватные маркеры, дамп `git log -p --all` | находки ниже |
| `public_data_check.scan_tree` | дерево (только файлы под git) | **0 находок** после правок: 169 файлов в `simintech-code`, 57 в `simintech-mcp`, 27 в `simintech-skill` |

## Что нашлось в истории

Образцы приводятся **обезличенно**: отчёт, который дословно цитирует то, что
признано следом, сам становится новым тиражированием. Число вхождений
указано как `code/mcp/skill`.

| Находка | Правило | Разбор |
|---|---|---|
| адрес коммитов GitHub (`…@users.noreply.github.com`) ×10/×7/×7 | email | **Публичное**: адрес, выданный GitHub для сокрытия настоящего. Домен внесён в allowlist |
| частный адрес из RFC 1918 ×9/×3/×3 | private-ip | **Синтетика** в тесте `dbconf`; в дереве заменён на документационный `192.0.2.5` (RFC 5737) |
| UNC-путь и именованный канал | unc-path | **Синтетика** в примерах и тестах разбора путей |
| частные адреса в примерах правил ×4/×2/×2 | private-ip | **Синтетика**: тесты гейта и план |
| придуманный адрес во «внутреннем» домене ×2/×1/×1 | email | **Синтетика**: для проверки правила |
| путь к домашнему каталогу с именем профиля ×3/×2/×2 | user-profile | **След рабочего окружения**. В дереве заменён на синтетический профиль; в истории остаётся |
| абсолютный путь с именем рабочего проекта | (правило текстовых путей убрано) | **След рабочего окружения**. В дереве заменён на нейтральный; в истории остаётся |
| `KBA_CTL - генерация кода для АЭС/kba.pak` | — | **Публичное, проверено фактом**: каталог есть в поставке вендора (`C:\SimInTech64\Demo\Интеграция со сторонним ПО\…`), то есть имя видит любой пользователь SimInTech. Оставлено осознанно |

Про `KBA_CTL` отдельно: без проверки это выглядело бы как упоминание
заказчика. Проверка выполнена (`find` по поставке) — оказалось именем
демонстрационного пакета вендора. Именно так и должен разбираться каждый
подобный случай: сначала источник, потом вывод.

## Что сделано

- из дерева убраны следы рабочего окружения: имя профиля и путь `D:\project\`;
- синтетические примеры приведены к явно синтетическим (документационный
  диапазон адресов, обезличенный профиль);
- публичный адрес коммитов GitHub внесён в allowlist гейта, чтобы скан истории
  не краснел на том, что публично по определению.

## Что осталось и требует решения владельца

**История уже опубликована.** Репозитории выложены на GitHub 26 сентября, и
перечисленные следы окружения (имя Windows-профиля и путь с именем рабочего
проекта) находятся в уже отправленных коммитах. Удалить их из истории можно
только перезаписью
(`git filter-repo` + force-push), а это:

- ломает клоны у всех, у кого они есть;
- запрещено политикой репозитория (force-push в `main` блокируется хуком);
- для этих данных не требуется: это не секреты и не персональные данные в
  юридическом смысле, а фрагменты путей; риск — низкий.

**Решение:** оставить как есть и не повторять (гейт не даст), либо, если
владелец считает иначе, — перезапись истории отдельным согласованным действием
с предупреждением всех, у кого есть клоны.
