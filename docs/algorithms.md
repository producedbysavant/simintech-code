# Алгоритмы размещения и трассировки

Описание алгоритмов из `simintech_api/layout/`. Пространство схемы SimInTech —
декартовы координаты в пикселях; оси: X растёт вправо, Y — вниз (как в
графических редакторах).

## LayeredPlacer — размещение блоков

Реализует схему «слои по направлению сигнала» (адаптация алгоритма
Sugiyama для горизонтального потока слева направо).

### Шаг 1. Ранжирование (слои)
- Блоки без входных связей → **слой 0**.
- Блок, у которого все источники уже в слоях ≤ N и хотя бы один в слое N →
  **слой N+1**.
- **Обратная связь / чистый цикл**: если граф не имеет блоков без входов,
  корнем назначается блок с минимальным числом входов, он исключается из
  зависимостей остальных (его обратные связи не формируют новый слой). Это
  позволяет размещать регуляторы с замыканием обратной связи.

### Шаг 2. Упорядочивание внутри слоя
**Медианная эвристика** (минимизация пересечений линий между соседними
слоями): для каждого блока слоя N+1 вычисляется медиана позиций его
источников в слое N; блоки сортируются по этой медиане.

### Шаг 3. Координаты
- Каждый слой занимает свою колонку по X: `x = cx0 + layer_index * layer_gap`.
- Внутри слоя блоки раскладываются по Y с равными промежутками `block_gap`,
  колонка вертикально центрируется относительно самой высокой колонки
  компоновки.
- Размеры блоков берутся из аргумента `sizes` (по умолчанию 60×40).

### Шаг 4. Постобработка
- Вертикальное центрирование колонок.
- Проверка отсутствия наложений (гарантируется геометрией: зазоры ≥ block_gap).

### Сложность
Ранжирование O(V+E), упорядочивание — O(k·log k) на слой, где k — размер
слоя. Для 200 блоков — доли секунды (см. `tests/unit/test_performance.py`).

## AStarRouter — расчёт ортогонального маршрута

Считает ортогональные (только по горизонтали/вертикали) пути между портами на
дискретной сетке.

**Это только расчёт.** Геометрию линии задаёт SimInTech (`NormalizeWire`
после перерисовки редактора): передать ему свои изломы нечем — `SetWirePoint`
на линии без размеченных точек нормализация игнорирует, а на размеченной даёт
зигзаг (`docs/reference/com_api_inventory.md` §6). Поэтому результат `route()`
нельзя принять за трассировку схемы: чистая схема получается расстановкой
блоков (`LayeredPlacer`), а `create_wire(points=…)` маршрутом не управляет.

### Шаг 1. Построение сетки
- Узлы сетки с шагом `grid_size` (по умолчанию 20 px).
- Блоки добавляются как прямоугольники **с отступом 1 узел** вокруг — линии
  не идут вплотную к блокам.
- Уже проложенные линии могут добавляться как препятствия (повышенная
  стоимость), чтобы минимизировать пересечения.

### Шаг 2. «Вылет» из порта
Чтобы линия выходила перпендикулярно стороне блока, старт и цель
сдвигаются по нормали к стороне порта (`_stub_from_port`). Стороны —
из `PortSide` (LEFT/RIGHT/TOP/BOTTOM), берутся из `Port.get_side()`.

### Шаг 3. A* на сетке
- Движение по 4-соседям (манхэттенская метрика).
- **Штраф за повороты** (`turn_penalty`): смена направления дороже прямого
  продолжения → линии более «прямые», меньше изломов.
- Эвристика — манхэттенское расстояние. Открытый список — бинарная куча
  (`heapq`).

### Шаг 4. Спец-случаи
- Старт и цель в одном узле / рядом → `[]` (прямое соединение).
- **Свободная прямая** между вылетами (`_straight_free`) → `[]` (прямое
  соединение; `NormalizeWire` сделает линию прямой автоматически).

### Шаг 5. Сглаживание
Удаление промежуточных точек, лежащих на одной горизонтали/вертикали
(`_smooth`) — каждая поворотная точка остаётся, коллинеарные отбрасываются.

### Невозможный путь
Если A* исчерпал открытый список — бросается `LayoutError`.

## Использование вместе

```python
from simintech_api.layout import LayeredPlacer, AStarRouter, ObstacleGrid

# 1. Расставить блоки — от расстановки зависит геометрия линий
placer = LayeredPlacer()
positions = placer.place(block_ids, connections, sizes=sizes)

# 2. Соединить порты: маршрут выбирает SimInTech, точек не передаём
for src, dst in connections:
    out_p = blocks[src].get_out_port(0)
    in_p = blocks[dst].get_in_port(0)
    wire = page.create_wire(out_p, in_p)

# 3. (Необязательно) Посчитать ортогональный маршрут — только для проверок
#    геометрии: применить его к линии нельзя (см. предупреждение выше).
router = AStarRouter()
grid = ObstacleGrid(200, 120)
for bid, (cx, cy) in positions.items():
    w, h = sizes[bid]
    grid.add_rect(cx - w/2, cy - h/2, w, h)
out_p = blocks["src"].get_out_port(0)
in_p = blocks["dst"].get_in_port(0)
route = router.route(out_p.get_coords(), in_p.get_coords(), grid,
                     start_side=out_p.get_side(), end_side=in_p.get_side())
print(f"опорных точек: {len(route)}")   # в линии эти точки не попадут
```
