# Матрица совместимости трёх репозиториев

Три репозитория связаны жёстко: MCP-сервер зависит от библиотеки по
**релизному тегу `vX.Y.Z` с якорем-коммитом** (`# sha:` — политика 2026-10-01:
теги `v*` неизменяемы ruleset'ом, якорь ловит перестановку тега; см.
`simintech-mcp/pyproject.toml`), а скиллы пересказывают данные библиотеки.
Документ фиксирует, какое сочетание версий проверено и что нужно сделать,
чтобы его сменить.

|---|---|---|---|
| 0.7.0, `b77f6594…` | 0.2.0, пин на `b77f6594…` | 0.2.0 | ✅ проверено: CI зелёный (check + secrets + public-data), `scripts/check_pins.py` — OK |
| 0.15.0, `bb5de99…` (main) | 0.2.0, пин `v0.14.0` (якорь `ff87db18…`) | 0.2.0, `603c543…` (main) | ✅ проверено 2026-10-16: CI трёх репозиториев зелёный. MCP стоит на релизном теге `v0.14.0`; возможности main (0.15.0 — запуск макроса через `mstarter`) ещё не подключены |

## Что означает «проверено»

| Проверка | Где | Что ловит |
|---|---|---|
| Пин существует в origin | `simintech-mcp/scripts/check_pins.py` (шаг CI до установки) | Исчезнувший коммит: сообщает именем и SHA, а не `upload-pack: not our ref` |
| В библиотеке есть нужный API | `simintech-mcp/tests/unit/test_dependency_contract.py` | Коммит жив, но символов (`Project.from_template`, `language.*`, …) в нём нет |
| Пересказ скиллов совпадает с данными библиотеки | `simintech-skill` CI: checkout `simintech-code` + сверка с `constants.py` и `block_catalog.json` | Дрейф знания: «12 классов» против 958 |
| Таблица инструментов в README не отстала | `simintech-mcp/tests/unit/test_surface.py` | Документация, отставшая от `tools/list` |

## Как поднимать пин (порядок обязателен)

1. Изменения вливаются в `simintech-code`; убедиться, что CI там зелёный.
2. Выпускается **релизный тег** `vX.Y.Z` (теги `v*` защищены ruleset'ом
   `protect-release-tags`: удаление и перезапись запрещены). Якорь `# sha:` в
   `simintech-mcp/pyproject.toml` фиксирует peeled-коммит тега; `check_pins.py`
   сверяет с якорем разрешение тега и `__version__` внутри коммита — вторая
   проверка ловит ловушку «тег стоит на чужом коде».
3. Обновить строку зависимости и комментарий-якорь в
   `simintech-mcp/pyproject.toml`.
4. Прогнать в MCP: `scripts/check_pins.py`, `test_dependency_contract.py`,
   полный `pytest tests/unit`.
5. **Публикация — сначала `simintech-code`, потом `simintech-mcp`.** Обратный
   порядок оставит пин на тег, которого на origin ещё нет; `check_pins.py`
   это назовёт, но CI будет красным.
6. Обновить таблицу выше (дата фиксации — обязательна).

## Чего здесь нет

- **Обратной совместимости не обещано.** Библиотека в 0.x, API меняется вместе
  со знанием о среде; пин и фиксирует это.
- **Автоматического обновления пина нет намеренно.** В `simintech-mcp` он внесён
  в `ignore` Dependabot: обновление ядра требует, чтобы новый коммит уже
  существовал в origin, и проверяется контрактным тестом — это решение
  человека, а не бота.
